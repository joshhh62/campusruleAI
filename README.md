# CampusRule AI

A retrieval-augmented assistant for university academic policy. Ask a question in plain English ("Can I retake an exam if I was sick?") and CampusRule AI finds the relevant clauses across 48 policy PDFs, streams an answer from a local LLM and cites the documents it used.

**3rd place, AIESEC Hackathon 2025** · [Project report](CampusRuleAI_Report.pdf) · [Slides](CampusRule_AI.pptx)

---

## What it does

- **Hybrid retrieval:** FAISS semantic search (MiniLM embeddings) blended with BM25 keyword matching, so both paraphrased questions and exact policy terms land on the right clause
- **Grounded answers, streamed:** a local LLM through Ollama (`gemma:7b` by default) answers from the retrieved chunks over Server-Sent Events, with source citations on every reply
- **Keeps working without the LLM:** if Ollama isn't running, answers fall back to RoBERTa extractive QA (`deepset/roberta-base-squad2`), which can only quote the source text
- **Conversation memory:** multi-turn chats stored in SQLite, with pinning, history and export to TXT, Markdown, DOCX or PDF
- **Understands the question:** intent detection, follow-up suggestions and a trie-based autocomplete that learns from frequent, similar and trending questions
- **Analytics dashboard:** questions asked, response times, confidence, trending topics and user feedback
- **Extras for students:** side-by-side policy comparison, a policy relationship graph and a GPA calculator
- **Bring your own documents:** upload a PDF and the index rebuilds

## Architecture

```
                    ┌────────── FAISS (MiniLM, cosine) ──┐
question ─► intent ─┤                                    ├─► 0.7 · semantic + 0.3 · keyword ─► top-5 chunks
                    └────────── BM25 (keyword) ──────────┘                                         │
                                                                                                   ▼
                                          Ollama (gemma:7b) streams a cited answer  ──or──  RoBERTa extracts a span
                                                                                                   │
                                     SQLite: conversation memory · analytics · feedback ◄──────────┘
```

| Piece | Choice |
|---|---|
| PDF parsing | `pdfplumber`, 400-word chunks with 80-word overlap |
| Embeddings | `all-MiniLM-L6-v2` (384-dim) |
| Vector index | FAISS `IndexFlatIP` on L2-normalised vectors (cosine similarity) |
| Keyword search | `rank-bm25` (BM25Okapi) |
| Generation | Ollama, `gemma:7b` (configurable) |
| Fallback QA | `deepset/roberta-base-squad2` |
| Storage | SQLite for conversations, analytics and autocomplete |
| Frontend | React, Vite, Tailwind CSS |

The policy corpus is 48 PDFs for the fictional Westbrook University, generated by `pdf_generator.py`, so the whole project can be rebuilt from scratch on any machine.

## Quick start

### 1. Backend

```bash
cd backend
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt

python pdf_generator.py         # (re)generate the 48 policy PDFs
uvicorn main:app --reload --port 8000
```

On first start the backend parses and chunks the PDFs, downloads the embedding and QA models (~600 MB) and saves the FAISS index to `data/`. Later starts load the cached index.

### 2. Local LLM (optional, recommended)

```bash
ollama pull gemma:7b
ollama serve
```

Without Ollama the app still answers, using extractive QA. `GET /api/health` reports whether the model is reachable.

### 3. Frontend

```bash
cd frontend
npm install
npm run dev
```

Open [http://localhost:5173](http://localhost:5173)

### Configuration

| Variable | Default |
|---|---|
| `OLLAMA_BASE_URL` | `http://localhost:11434` |
| `OLLAMA_MODEL` | `gemma:7b` |
| `EMBEDDING_MODEL` | `all-MiniLM-L6-v2` |
| `QA_MODEL` | `deepset/roberta-base-squad2` |
| `CHUNK_SIZE` / `CHUNK_OVERLAP` | `400` / `80` words |

## API

| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/api/chat` | Chat with retrieval; set `stream: true` for SSE |
| `POST` | `/api/search` | Hybrid search + extractive QA |
| `POST` | `/api/autocomplete` | Question suggestions as you type |
| `GET` | `/api/conversations` | List conversations |
| `GET` / `DELETE` | `/api/conversation/{id}` | Read or delete a conversation |
| `POST` | `/api/conversation/{id}/pin` | Pin a conversation |
| `POST` | `/api/feedback` | Rate an answer |
| `GET` | `/api/analytics` | Usage and quality metrics |
| `POST` | `/api/export` | Export a conversation (txt, md, docx, pdf) |
| `GET` | `/api/documents` | List indexed documents |
| `POST` | `/api/upload` | Upload a PDF and re-index |
| `DELETE` | `/api/documents/{filename}` | Remove a document |
| `POST` | `/api/admin/reindex` | Rebuild the index |
| `GET` | `/api/health` | Index and Ollama status |

### Example: `/api/search`

```json
{ "query": "How many absences am I allowed?", "top_k": 5 }
```

## Project structure

```
campusruleAI/
├── backend/
│   ├── main.py            # FastAPI app and routes
│   ├── retrieval.py       # PDF parsing, chunking, FAISS + BM25 hybrid search, RoBERTa QA
│   ├── rag.py             # Ollama prompting, streaming, intent detection, follow-ups, fallback
│   ├── conversation.py    # SQLite conversation memory
│   ├── analytics.py       # SQLite usage and quality analytics
│   ├── predictor.py       # Trie-based autocomplete with multi-signal ranking
│   ├── models.py          # Pydantic request/response models
│   ├── pdf_generator.py   # Generates the 48 policy PDFs
│   └── data/documents/    # Policy PDFs
└── frontend/src/
    ├── pages/             # Chat, Dashboard, Analytics, Settings
    ├── components/        # Chat UI, citations, autocomplete, comparison, policy graph, GPA calculator, export
    └── hooks/             # useChat, useAutoComplete, useTheme, useLocalStorage
```

## Requirements

- Python 3.10+ and Node.js 18+
- ~1 GB disk for the embedding and QA models, plus ~5 GB for `gemma:7b`
- 8 GB RAM recommended when running the local LLM
